# Design Routing Kernel

Load for UI work. Route once: thin kernel → conditional Apple foundation → one specialist → evidence tool. Do not stack aesthetic generators.

## Foundation

- Load `clx-apple-design` for substantial UI creation, redesign, interaction/motion decisions, or UI review even when Apple is not named.
- Skip its body for non-UI work, exact copying with no unspecified behavior, and fully specified one-value UI patches.
- Apple foundation is not an aesthetic specialist; it owns unresolved feedback, directness, spatial continuity, and interaction physics.
- An explicit no-Apple request disables only the Apple foundation; specialist and Astryx eligibility still follow their own independent conditions.

## Mutually-exclusive specialist

- Exact declared reference/Figma reproduction → preserve it without an aesthetic generator; add `clx-figma-workflow` only when Figma mechanics are involved.
- New UI → `clx-frontend-design`.
- Existing UI critique/polish → `impeccable`.
- Explicit immersive/3D technology → `clx-immersive-web`; use it alone when it fully owns the request, or add it to the one new/existing aesthetic branch when that direction/polish is also requested. Never for ordinary motion.
- Ambiguous scope → use `clx-grill-me` to clarify, then choose exactly one branch above.
- Concrete overlap, clipping, spacing, or breakpoint defect with no aesthetic redesign → apply the core and browser evidence directly; no specialist.

Tiny, explicit fixes need no specialist.

An explicit narrow helper (`clx-theme-factory`, `clx-color-expert`, named `clx-vercel-web-design-guidelines`, or post-build `clx-playwright`) wins over a general specialist when it fully owns the request; industry or brand-mood palette selection belongs to `clx-color-expert` (`references/industry-palettes.md` — direction only; validate and repair every foreground/background pair before any hex ships). UI UX Pro Max is a conditional local reference inside `clx-frontend-design`, never another specialist.

Pure prose cleanup exits the design lattice and routes only to `clx-unslop`; when bundled with UI work, it remains an orthogonal process asset, not a specialist or design helper.

Static poster/print → `clx-canvas-design`; seeded generative art → `clx-algorithmic-art`; explicit Excalidraw sketch → `clx-hand-drawn-diagrams`. These are non-UI media routes: skip Apple, frontend, impeccable, and Astryx. Use native Mermaid when sufficient.

## Implementation and evidence

- General no-bounce guidance applies to decorative motion. A restrained overshoot is eligible only after a momentum-carrying flick, throw, or drag release; never for a menu, modal, page entrance, automatic reveal, or reduced-motion path.
- Do not infer momentum from `drag`, `reorder`, `sheet`, `carousel`, or unspecified physics. Require explicit flick, throw, momentum, velocity, or velocity-carrying release evidence.
- Astryx is eligible only for new React work with no established design system; inspect the repository first and otherwise reuse its system. Treat Astryx as a component/accessibility foundation, not an aesthetic specialist, and verify its current Beta API through official CLI/docs. When eligible, load skill `clx-astryx` (vendored manifest/CLI snapshot) as the integration guide. Do not install or migrate to Astryx for existing UI polish, exact reproduction, or non-React work.
- Every design task uses 1–`min(7, available slots, independent lenses)` scoped subagents under `work/subagents`; at most one writer, and exactly one only when writes occur. Other reviewers are read-only; no recursive spawn; release completed agents immediately.
- `clx-playwright` is post-build browser evidence only, never a design generator or pre-build requirement.
- UX/UI friction panel: on an explicit UX inspection request (UX 점검, 불편한 점 검사) or post-build review of substantial UI, run the standing read-only reviewers `ux-friction-reviewer` · `ui-visual-inspector` · `a11y-motion-auditor` in parallel under one shared direction brief (findings only, no writes); main reconciles and owns fixes.
- Verify with the repository's build/tests, then browser evidence when a runnable UI exists. Exercise supported narrow, mid, and wide viewports plus long/localized copy and 200% zoom; release only with accidental overlap, clipping, horizontal overflow, or hit-area collisions: zero. Intentional overlays need explicit evidence that content and controls remain usable.
