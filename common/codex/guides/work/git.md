# Git Rules

Attribution: never add `Co-Authored-By` or any AI/agent attribution to commits, PRs, or code; human tone, no "generated by" markers.

Commits: message focuses on why, not a file list; one logical change per commit; never commit secrets (`.env`, keys, credentials).

Safety: no destructive git (`--force`, hard reset) unless user explicitly requests; no `--no-verify`/hook skips unless requested; no force-push to `main`/`master` without explicit approval. Structurally enforced by `hooks/guard-destructive.py` (PreToolUse). The exact command, target, side effects, rollback, and remote verification belong in the approved development specification before a grant is requested. For one guarded command, its CLI-minted `승인 <ID>: <command>` line may also approve that development specification. Multiple guarded commands use one development-spec approval followed by command-specific grants; never repeat the specifications. Finish all other safe work first. Never output a bare challenge as the whole response; keep the exact grant on the final line and resume automatically when the owner returns it alone. UserPromptSubmit records the single-use SHA-256 approval. A trusted Codex transcript fallback accepts only the latest real one-line `user_message` when that event is skipped; assistant/tool text, stale prompts, and command mismatches cannot mint. The agent never writes the ledger, challenge store, or `settings.json`, and `guard-destructive.py` allows the exact command once. No override of any kind: Keychain/auth, Chrome profile writes, proven writes to agent session/runtime state, enforcement config, or a fail-closed guard. The owner can always run a command directly in their own terminal.

PRs: same attribution ban; summarize why, include test plan when non-trivial.
